# FINN — Build Plan for Claude Code

FINN is a mobile-first financial investment agent for the ENAM Holdings AI Engineer Build Challenge.
**Push** tells the investor what changed and why it matters. **Pull** researches any NSE company from
primary sources only (annual reports, concall transcripts, exchange filings).

Point of view: FINN is an **editor that sends a finite brief**, not a terminal that streams everything.
- The brief ends; "you're caught up" is the goal.
- Every number has a receipt (tap → source page).
- The investor owns the filter (thresholds are editable sentences; every card says why it's there).

---

## 0. Working rules for Claude Code

1. Work **one phase at a time**. A phase is done only when every acceptance criterion passes. Run the
   checks yourself (tests, curl, opening the deployed page) and paste the evidence in the commit message.
2. The modules in `backend/finn/sources/fetchers.py`, `backend/finn/llm.py` and `backend/finn/push/*.py`
   already exist. **Keep their public function signatures.** Extend them; don't rewrite them.
3. **No number is ever generated by an LLM.** Numbers come from tables, XBRL, or LLM *copying* followed
   by validation. Every LLM output that contains numbers passes `pull/numcheck.py` (§6.4).
4. **Pull uses primary sources only.** No web search, no news, no model background knowledge. Push-side
   people enrichment (management bios) may use web search.
5. Every LLM call goes through `finn.llm.complete_json(tier, system, prompt)`, which caches by content
   hash. Use `cheap` for extraction and `strong` only where §5 says so.
6. **Degrade per card, never per page.** A failing card renders its reason; the rest of the page still works.
7. Commit after each milestone with a descriptive message. Keep `docs/build-history/` updated (§8.3).
8. Times are stored in UTC and displayed in IST. Quarters are keyed by period-end date (`YYYY-MM-DD`).

## 1. Architecture

```
yfinance ─┐                ┌──────────────── Push jobs (GitHub Actions cron) ──► Telegram
BSE/NSE ──┼──► fetchers ───┤                         │
screener ─┘                └── Pull API (FastAPI on HF Spaces) ◄────┐           │
                                         │                          │           ▼
                                         └──────► Supabase Postgres ◄───────────┘
                                                        │  (anon read, RLS)
                                                        ▼
                                          Next.js PWA on Vercel (phone link)
                                          + bundled demo snapshot (static JSON)
```

| Layer | Choice |
|---|---|
| Frontend | Next.js 15 App Router + TypeScript + Tailwind, installable PWA, Vercel Hobby |
| Push jobs | Python 3.12 on GitHub Actions cron (public repo) |
| Pull API | FastAPI in Docker on Hugging Face Spaces (CPU basic, port 7860) |
| DB | Supabase Postgres (free). Frontend reads with the anon key; jobs and API write with the service key |
| LLM | cheap = Gemini Flash (free tier); strong = Claude Sonnet. Both env-configurable |
| Alerts | Telegram bot |
| People search | Tavily API (free tier), Push management bios only |

Push needs no running server: the jobs write to Supabase and the PWA reads it directly. Only Pull and
writes to settings go through the API.

## 4. Data schema and API contracts

### 4.1 Postgres schema (`supabase/schema.sql`)

```sql
create table companies (
  symbol text primary key, name text, isin text unique, bse_code text, sector text,
  mcap_cr numeric, is_financial boolean default false,
  in_portfolio boolean default false, in_research_set boolean default false,
  updated_at timestamptz default now());

create table prices (
  symbol text references companies, date date, open numeric, high numeric, low numeric,
  close numeric, volume bigint, primary key (symbol, date));

create table filings (
  id text primary key,                       -- 'BSE-<newsid>' | 'NSE-<seq_id>'
  symbol text references companies, isin text, ts timestamptz not null,
  subject text, text text, url text, src text,
  category text, subtype text, secondary text[], method text,
  score numeric, tier text check (tier in ('act','know','routine')), reasons text[],
  card jsonb,                                 -- one of the Push card types (§4.2)
  card_status text default 'none',            -- none|pending|ready|failed
  created_at timestamptz default now());
create index filings_ts on filings (ts desc);
create index filings_symbol_ts on filings (symbol, ts desc);

create table alerts (
  id bigserial primary key, dedupe text unique, symbol text, kind text,
  ts timestamptz default now(), title text, reasons text[], payload jsonb,
  seen boolean default false, sent boolean default false);

create table settings (
  id int primary key default 1 check (id = 1),
  vol_multiple numeric default 2, vol_lookback int default 20, min_avg_volume numeric default 10000,
  price_move_pct numeric default 5, relative_to_index boolean default false,
  alert_categories text[] default '{results,M&A,management_change,litigation,pledging,credit_rating}',
  min_category_tier text default 'know',
  overrides jsonb default '{}',              -- {"BSE": {"price_move_pct": 8}}
  weights jsonb default '{}',                -- {"dividend.cash": 0.05}  (overrides score.BASE)
  updated_at timestamptz default now());
insert into settings (id) values (1) on conflict do nothing;

create table docs (
  url text primary key, symbol text, kind text,   -- transcript|annual_report|results|filing
  period text, pages jsonb,                       -- ["page 1 text", "page 2 text", ...]
  sections jsonb,                                 -- AR only: {"mdna": [page numbers], ...}
  ocr_needed boolean default false, fetched_at timestamptz default now());

create table analyses (
  symbol text, card text,                         -- see ResearchCardId in §4.2
  status text,                                    -- queued|running|ready|gap|failed
  data jsonb, citations jsonb, gaps text[], prompt_version text,
  updated_at timestamptz default now(), primary key (symbol, card));

create table jobs (
  id uuid primary key default gen_random_uuid(), symbol text, kind text default 'research',
  status text, error text, started_at timestamptz default now(), finished_at timestamptz);

-- Read access for the PWA (anon key)
do $$ declare t text; begin
  foreach t in array array['companies','prices','filings','alerts','settings','analyses','jobs'] loop
    execute format('alter table %I enable row level security', t);
    execute format('create policy anon_read on %I for select using (true)', t);
  end loop; end $$;
-- docs stays private: receipts are served through the API (§4.3)
```

export interface ResearchPayload {
  symbol: string; name: string; basis: "consolidated" | "standalone"; is_financial: boolean;

  cards: Partial<Record<ResearchCardId, ResearchCard>>; gaps: string[];

### 4.3 Pull API (`backend/api/main.py`)

All responses are JSON. CORS allows the Vercel origin. Errors: `{"error": "<code>", "detail": "<human message>"}`.

| Method & path | Request | Response | Notes |
|---|---|---|---|
| `GET /health` | — | `{"ok": true, "version": "…"}` | Pinged by the keepalive workflow and on app load |
| `POST /research/{symbol}` | `?refresh=0\|1` | `202 {"job_id": uuid, "status": "queued"}` or `200 ResearchPayload` if fresh (< 24h) | Validates against NSE `EQUITY_L`; `404 {"error":"unknown_symbol"}` |
| `GET /research/{symbol}` | — | `ResearchPayload` | Frontend polls every 2s while `status != ready`. Number cards are ready within ~5s |
| `GET /receipt` | `?citation_id=` or `?doc_url=&page=&q=` | `{"doc_url", "kind", "period", "page", "text", "highlight": [start, end]}` | `q` = quote to highlight (fuzzy match) |
| `POST /ask` | `{"symbol": str, "question": str, "context": {"card": ResearchCardId?, "citation_id": str?}}` | `{"answer": str, "citations": Citation[], "not_found": bool}` | Header `X-FINN-Token` |
| `PUT /settings` | partial `settings` row | updated row | Header `X-FINN-Token` |
| `POST /alerts/{id}/seen` | — | `{"ok": true}` | Header `X-FINN-Token` |

Direct Supabase reads from the PWA: `filings` (window), `alerts` (window), `companies`, `prices`
(last 60 days for sparklines), `settings`, `analyses`.

### 4.4 Push pipeline contract (`push/pipeline.py`)

```
run_poll(start, end):
  rows   = bse_announcements(...) [+ nse_announcements(...) if FINN_USE_NSE]
  rows   = dedupe(rows)                       # ISIN + ts ±10 min + normalised subject
  for r in new rows for portfolio ISINs:
      cats   = classify(r.subject, r.text, r.category)
      scored = score_filing(cats, r.subject, r.text, mcap_cr, settings.alert_categories,
                            same_day_move_pct)            # apply settings.weights over BASE
      card   = build card only if scored.tier in (act, know):
                 results            → results.results_card(xbrl, pdf_pages, is_financial, history, url)
                 management_change  → mgmt.mgmt_card(pdf_pages, company_name, url)
                 others             → oneliner.oneliner(category, subject, pdf_pages, url)
      upsert filings row; category_alerts → alerts (dedupe) → Telegram
run_eod():
  prices = eod_prices(portfolio) (fallback bhavcopy_history); upsert prices
  alerts = eod_alerts(prices, settings, nifty, filings_last_24h) → alerts → Telegram
  refresh companies.mcap_cr from screener top ratios (weekly is enough)
```

## 5. Prompts (exact text, in `pull/prompts.py` and the existing push modules)

All prompts are called through `llm.complete_json`, which appends
` Respond with a single JSON object and nothing else.` to the system prompt.
Placeholders are `{like_this}`. Bump `FINN_PROMPT_VERSION` whenever a prompt changes.

**Shared grounding preamble** (prepended to every Pull system prompt):

```
You are FINN's analyst. You work ONLY from the excerpts and tables provided in this message.
Do not use any outside knowledge about the company, its industry, its peers or the market.
Every factual statement must cite the id of an excerpt or table row you were given.
If the provided material does not support a statement, leave it out or say "not disclosed in sources".
Never calculate new numbers; only use numbers that appear in the material provided.
```

### P1 — Filing classification fallback (cheap) · `push/classify.py`
Used only when no regex rule and no exchange category hint matched.

```
SYSTEM: You classify Indian stock-exchange corporate announcements.
USER:
Categories: results, M&A, fund_raise, management_change, litigation, insider_trading, earnings_call,
investor_meetings, credit_rating, dividend, bonus_split, capex, press_release, postal_ballot, agm_egm,
pledging, unclassified.
Return {"category": one of the categories, "subtype": short snake_case label}.

Subject: {subject}
Text: {first_1500_chars}
```

### P2 — Results table extraction (cheap) · `push/results.py`

```
SYSTEM: You copy numbers from Indian listed-company quarterly results tables. Copy each number exactly
as printed (brackets mean negative). Never compute, round or estimate. Use null when a line is not printed.
USER:
From the results table below, return JSON:
{"basis": "consolidated" | "standalone", "unit": "crore" | "lakh" | "million" | "thousand" | "rupees",
 "page": <page number used>, "columns": [{"label": "<column header as printed>",
 "period_end": "YYYY-MM-DD", "months": 3, <fields>}]}
Fields: {fields}.
Prefer the consolidated table if both are present. Include every 3-month column (current quarter,
preceding quarter, same quarter last year); skip half-year and full-year columns.

[page {n}]
{page_text}
```
`{fields}` for companies: `revenue (Revenue from operations), other_income, finance_costs, dep (Depreciation
and amortisation), exceptional (Exceptional items; gain positive, loss negative), pbt (Profit before tax,
after exceptional items), tax (Total tax expense), pat (Net profit for the period)`.
For banks/NBFCs: `interest_earned (Interest earned / Interest income), interest_expended (Interest expended /
Finance cost), operating_profit (Operating profit before provisions and contingencies), provisions
(Provisions and contingencies, excluding tax), pbt, tax, pat (Net profit for the period)`.

### P5 — One-liner for other categories (cheap) · `push/oneliner.py`

```
SYSTEM: You summarise one Indian stock-exchange filing for a busy investor. Use only the filing text.
Copy numbers exactly as printed. Do not add context, opinions or anything not in the filing.
USER:
Category: {category}
Extract these facts (null if not stated): {facts_for_category}
Then write "line": one sentence, at most 20 words, leading with the single most decision-relevant fact.
Return {"facts": {...}, "line": str, "page": int|null}

Subject: {subject}
[page 1]
{page_text}
...
```
`{facts_for_category}`:

| Category | Facts |
|---|---|
| M&A | target, stake_pct, consideration_inr, consideration_type (cash/stock/mixed), related_party (yes/no), expected_completion |
| fund_raise | instrument, size_inr, price_per_share, discount_to_cmp_pct (only if printed), investors |
| capex | project, amount_inr, capacity_added, location, commissioning_date |
| litigation | authority, amount_inr, nature, status (order/notice/appeal), next_date |
| credit_rating | agency, instrument, old_rating, new_rating, outlook, action |
| insider_trading | person, relation (promoter/director/KMP), buy_or_sell, shares, value_inr, holding_after_pct |
| pledging | promoter_entity, shares, action (create/release/invoke), pledged_pct_after |
| dividend | type (interim/final/special), per_share_inr, record_date, payment_date |
| bonus_split | ratio, record_date |
| press_release | headline_fact, value_inr, counterparty, duration |
| earnings_call | date, time_ist, dial_in_or_link |

### P9 — Promised vs delivered (strong) · `pull/ledger.py`
`ledger.py` first does the deterministic work:
1. Merge P7 outputs across the last 4 transcripts into guidance threads (same `metric` + `horizon`).
2. Map each thread to a table metric. For example, `revenue_growth` + yoy maps to Sales growth computed from
   the screener quarterly or annual table, and `ebitda_margin` maps to `OPM %`.
3. Compute actuals and **deterministic verdicts** where the horizon has passed and the metric is in the
   tables: within [lo, hi] → delivered; above hi → beat; below lo by ≤10% relative → partial; else missed;
   horizon not reached → pending; no table metric → not_verifiable.
4. Detect revisions: the same thread with a different target in a later call.

The strong model then only judges the items code could not, and writes notes:

```
SYSTEM: {grounding_preamble}
You audit management's track record: what they promised versus what the numbers show.
USER:
Company: {company}.
Guidance threads (code has already computed verdicts where possible; do NOT change those):
{threads_json}      // each: id, metric_label, per-call {period, quote, citation, target, horizon},
                    //       actual, actual_citation, verdict (null where undecided), revisions
Actuals table (the only numbers you may use):
{actuals_table}     // rows: TBL-<section>-<metric>-<period> = value
Return {"items": [{
  "id": "<thread id>",
  "verdict": "delivered" | "beat" | "partial" | "missed" | "pending" | "not_verifiable",  // fill only where null
  "note": "<= 20 words: what was said vs what happened, using only numbers above>",
  "citations": ["<chunk id>", "<table row id>"]}],
 "pattern": "<= 25 words: the overall pattern, e.g. consistently guides high on margins, delivers on growth>"}
For directional guidance ("margins should improve"), compare the direction with the actuals table.
If the actuals needed are not in the table, use not_verifiable.
```

### P13 — Ask FINN (cheap, escalate to strong if `not_found` is false and the answer needs reasoning across >3 excerpts) · `pull/ask.py`

### Deterministic cards (no prompt)
- **financials (D2):** TTM revenue, EBITDA margin (OPM %), PAT, ROCE, ROE, D/E from screener tables.
- **trajectory (D3):** 10-year sales, OPM %, PAT; 3-year and 5-year CAGR; "growing" or "compressing" tags by
  slope sign over the last 8 quarters.
- **balance_sheet (D4):** borrowings, D/E, debtor, inventory and payable days, cash conversion cycle, equity vs debt mix.
- **cash_quality (D5):** CFO/PAT per year for 5 years, FCF = CFO − capex (capex = investing outflow on fixed
  assets if the schedule is available, otherwise labelled "investing cash flow"). Flag when CFO/PAT < 0.7 for 3 consecutive years.
- **guidance (D7):** latest call's P7 output, grouped by metric.

Every deterministic number cites `TBL-<section>-<metric>-<period>`.

## 6. Cross-cutting implementation details

### 6.1 Chunk ids
- Transcript: `T{period}-p{page}-{turn_index}`, e.g. `T2026Q2-p7-3`. One chunk per speaker turn, split at
  1,500 characters.
- Annual report: `AR{year}-p{page}`. Only pages from `ar_sections` are stored.
- Table rows: `TBL-{section}-{metric}-{period}`, e.g. `TBL-quarters-OPM %-2026-09-30`.

### 6.2 Research job (`pull/run.py`)
1. Validate the symbol, then call `pull_bundle` and upsert `companies`.
2. Write the deterministic cards (financials, trajectory, balance_sheet, cash_quality) with status `ready`
   within ~5 seconds.
3. Fetch documents in parallel (threads, max 4), store `docs`, set `ocr_needed` flags.
4. Run P7 and P8 per transcript, cached by doc URL hash.
5. Run P6, then the ledger (deterministic + P9), then P10.
6. Run P11, then P12.
7. Every card that can't be built gets status `gap` with a specific reason, for example
   "No concall transcripts filed in the last 12 months".
8. Results are reused for 24 hours unless `refresh=1`.

### 6.3 Frontend data layer (`web/lib/data.ts`)
1. Try Supabase. If the newest `filings.ts` is older than 72 hours, or the request fails, load
   `/demo/*.json`.
2. Show `DataModeChip`: "Live" or "Demo data · as of {freeze_time}". Tapping it toggles the mode.
3. For Research, try `GET /research/{symbol}`. If the API is unreachable and the symbol is in the demo
   set, load `/demo/research/{symbol}.json`.

### 6.4 Number post-check (`pull/numcheck.py`)
- Extract every number in LLM-written text (`note`, `evidence`, `point`, `answer`, `verdict`, `line`) with
  a regex that handles ₹, %, bps, crore and lakh.
- Each number must match, within 1% relative or 0.5 absolute, a number in that card's provided inputs.
  Years and quarter labels are exempt.
- On failure: drop the offending bullet or row. If the card loses more than half its content, mark it
  `failed` with the reason "number check failed". Log every failure.
- Also drop any item whose citation ids weren't in the provided material.

### 6.5 Visual system (web)
- **Tokens:** paper `#F7F5F0`, ink `#1C1B19`, muted `#6B6A65`, hairline `#E3E0D8`, accent vermilion `#D2462B`
  (Act and alerts only). Dark mode: paper `#151514`, ink `#ECEAE4`, same accent.
- **Fonts:** Newsreader (headlines, verdicts), Inter (body), IBM Plex Mono with tabular figures (all numbers).
- 14px body text. ▲▼ plus sign for direction, so colour is never the only signal. 150ms expand and collapse.
- **Bottom nav:** Brief · Watch · Look up. Rules sits behind the avatar.

**Covering-note outline (`docs/writeup.md`)**

1. **What I built** (3–4 lines)
   - FINN is an editor, not a terminal: a finite daily brief that ranks every filing into Act, Know or
     Routine, explains why each item is there, and ends.
   - Triggers are configurable as sentences.
   - The results card shows verified QoQ and YoY numbers; management changes come with a sourced
     background of the incoming person.
   - Pull works on any NSE ticker. Its hero view is a **Promise ledger** (what management guided versus
     what they delivered), and every number opens its source page (**Receipts**).
2. **Key decisions and tradeoffs**
   - Numbers come from structured sources (XBRL, financial tables); LLMs only *copy* and are validated,
     with a post-check that strips unmatched numbers. This trades coverage for trust.
   - Classification is rules-first, with the LLM only for leftovers. This makes it cheap, deterministic
     and explainable, at the cost of an occasional miss.
   - Materiality is a transparent weighted table rather than an LLM "importance" score, so the user can
     tune it and see why.
   - Model routing: a cheap model for extraction, a strong model for 3 synthesis calls per company, and a
     content-hash cache. Include the measured ₹ figures from `cost.md`.
   - BSE is the primary feed because NSE blocks cloud IPs; NSE is best effort.
   - A PWA over native, so the reviewer needs only a link. Telegram covers push notifications.
   - Supabase plus GitHub Actions plus HF Spaces, all free. Push needs no server.
   - Demo snapshot fallback, so the graded demo never depends on scraping on the day.
   - Single-user demo auth (a shared token), acknowledged.
3. **What I deliberately left out:** native app and native push; voice; intraday data; vector database
   (transcripts fit in context; annual reports are sectioned by heading); multi-user accounts; LinkedIn
   scraping; full annual-report parsing; valuation and price targets.
4. **Where I'd take it next:**
   - Learning materiality weights from triage behaviour.
   - Segment-level promise tracking.
   - Peer comparisons built from primary sources only.
   - Intraday and announcement-time alerts.
   - Native push via Expo.
   - Auditor's report and related-party red-flag scans from the full annual report.
   - A shared team brief, so investors can annotate items together.
