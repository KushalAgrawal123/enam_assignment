## How we work

- You name the phase and I build only that phase. It ends with a report: what shipped, evidence (test output,
  curl, phone-size screenshots), any exit criterion not met, what to check on a real phone, and what I need for
  the next phase. Then the status table above is updated.
- Every phase ends deployed and demoable, and never breaks an earlier screen.
- Inside a phase the order is: riskiest unknown first, then backend, web, deploy. I commit at each milestone with the
  evidence in the message (BUILD_PLAN §0.1, §0.7).
- BUILD_PLAN §0 holds throughout: no number is generated by an LLM; Pull uses primary sources only; every LLM call
  goes through `llm.complete_json`; a failure degrades one card, never the page; times are stored in UTC and shown in IST.
- At each phase end I re-freeze the demo snapshot (Delta 8) and copy this project's Claude Code session logs into
  `docs/build-history/claude-code/`, keys scrubbed.
- Secrets live only in `finn/.env` and the platforms' secret stores. I never read `.env` back or print a value,
  because these sessions are published as build history.

## Deltas from BUILD_PLAN.md

1. **The "EXISTS" modules aren't here.** `sources/fetchers.py`, `llm.py` and
   `push/{classify,score,digest,alerts,results,mgmt}.py` are not in this workspace, and you
   confirmed you don't have them. I write each one in the phase that first needs it and define its signatures then.
2. **Phases rebalanced.** Without those modules, BUILD_PLAN's Phase 1 would be most of the backend, the whole web
   shell and four deployments. Pull numbers move to Phase 2 together with document ingestion, which is the riskiest
   Pull data work and is done before the LLM work that needs it. BUILD_PLAN Phases 4 and 5 merge into Phase 5.
   After Phase 2, Push and Pull both run end to end on a phone, which is where BUILD_PLAN's Phase 1 meant to land.
3. **The repo root is `finn/`**, as in BUILD_PLAN §2. The challenge PDFs stay outside it in `Docs/`, because ENAM's
   documents shouldn't go into a public repo. It also avoids a clash: on macOS's case-insensitive filesystem,
   `Docs/` and the repo's `docs/` would be the same folder.
4. **Model IDs.** `FINN_STRONG_MODEL=claude-sonnet-5` (`claude-sonnet-5-5` doesn't exist). The cheap tier stays
   Gemini Flash, and Phase 1 confirms the current Flash model ID and free-tier quota. If the quota throttles bulk
   extraction, an env var switches the cheap tier to `claude-haiku-4-5` ($1/$5 per million tokens; Sonnet 5 is
   $2/$10).
5. **The LLM cache and cost log live in Supabase** in a new table, `llm_cache` (response, tokens and ₹ per call),
   with `.cache/` as a local layer in front. GitHub Actions runners and HF Spaces have ephemeral disks, and
   `usage_summary()` has to total spend across all three runtimes for `docs/cost.md`.
6. **Installability is no longer a Lighthouse check.** Lighthouse 12 removed the PWA category, so installability
   is checked in Chrome DevTools → Application → Manifest and by installing on a phone. The Performance ≥ 85
   target stays.
7. **Receipts start in Phase 2** for table numbers. "Every number has a receipt" is the product's point of view,
   and table receipts are cheap. Phase 4 extends them to document pages with highlighted quotes.
8. **The demo snapshot is frozen at the end of every phase**, not only at the end. Q2 FY27 results must be filed by
   about 14 Nov (SEBI's 45-day limit), so a snapshot frozen while results are flowing has the richest Act tier.
   `jobs.warm --freeze` keeps the snapshot with the most Act items as the default.
9. **Supabase access without a secret key.** Jobs and the API read and write over Postgres using `SUPABASE_DB_URL`,
   the session-pooler connection string, which works over IPv4. The web app reads with the publishable key. So no
   secret or service-role key is stored at all. Supabase retires the legacy `anon` and `service_role` keys at the
   end of 2026, so `NEXT_PUBLIC_SUPABASE_ANON_KEY` becomes `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
10. **NSE is the primary filings feed; BSE is off.** BSE's API returns 403 to automated clients (`docs/sources.md`),
    and FINN doesn't try to get around that. NSE's announcements API works and carries more than BSE's: ISIN, NSE's
    own category, a text summary, the PDF and an XBRL flag. Every portfolio company is NSE-listed. `bse_code`
    stays empty. NSE answers GitHub's runners too (run 41624378582), so the jobs stay on Actions.
11. **The Pull API runs on Vercel, not Hugging Face Spaces.** You asked to keep the project simple, and Vercel runs
    FastAPI with no configuration on the account you already have: no Hugging Face account or token, no 48-hour
    sleep, no 30–60 s Docker cold start. It's a second Vercel project (`finn-api`) deployed from `backend/`,
    with functions allowed 300 s, which covers reading an annual report. Document ingestion is a separate,
    resumable `POST /research/{symbol}/ingest`, so the number cards never wait on PDFs. The "cold Space"
    exit criterion becomes "first request to a freshly deployed function".
12. **Results ladder: the filing PDF, then screener's quarterly table; no XBRL rung.** NSE's financial-results
    index (the XBRL source) stops in January 2025. The screener rung is verified by arithmetic: the table's
    own identities must hold for the current, previous and year-ago quarters, and the PDF rung (when a Gemini
    key exists) must agree with the table. Banks show Revenue, PBT and PAT, because screener's "financing
    profit" nets provisions and is often negative.
13. **The write token never reaches the browser.** BUILD_PLAN put it in `NEXT_PUBLIC_FINN_API_TOKEN`; that ships it
    to every visitor. Writes (Rules, alert seen) go through the web app's own server routes, which add the
    token from a server-only variable.

## Phase 1 — Foundations + live Brief on a phone

**Goal:** open a Vercel link on a phone, install it, and read a ranked brief of the portfolio's BSE filings for
the last 24h, 3d or 7d. Every item says why it's there, and the brief ends with "you're caught up". If live data
is unavailable, it falls back to a frozen snapshot.

**Build**
1. **Source spike (first).** From this machine and from a throwaway GitHub Actions run, hit the BSE announcements
   API, an XBRL results file, yfinance `.NS`, NSE `EQUITY_L.csv`, NSE bhavcopy and screener.in. Record pass/fail
   in `docs/sources.md`. If BSE refuses Actions IPs, the poll job runs on a local schedule (launchd) instead and
   nothing else changes.
2. **Scaffold `finn/`** per BUILD_PLAN §2: `git init` with `origin` set to the GitHub repo, `.gitignore`,
   `.env.example` (§3 with Deltas 4, 5 and 9),
   `CLAUDE.md` (§0 rules plus pointers to both plans), a README stub and a copy of BUILD_PLAN.md.
3. **Companies:** `scripts/resolve_companies.py` writes `supabase/seed_companies.sql` (symbol, name, ISIN, BSE
   code, sector, `is_financial`, portfolio/research flags). Market cap comes from yfinance for now.
4. **Schema:** `supabase/schema.sql` (§4.1 plus `llm_cache`), applied with `psql`.
5. **Backend core:** `config.py`, `db.py`, `models.py` (the Push types from §4.2), and `llm.py`, which provides
   `complete_json(tier, system, prompt)` with a content-hash cache, a per-call cost log and `usage_summary()`.
6. **Fetchers (Phase 1 subset):** `bse_announcements(start, end, scrip_codes)`, `nse_equity_list()`,
   `eod_prices(symbols, days)` with a `bhavcopy_history()` fallback, and `nse_announcements()` behind
   `FINN_USE_NSE`.
7. **Push core + tests:**
   - `classify.py`: exchange category hint first, then regex rules, then the P1 LLM fallback.
   - `score.py`: BASE weights by category.subtype, modifiers for market cap and same-day move,
     `settings.weights` overrides, tier cut-offs and human-readable reasons.
   - `digest.py`: windows, tiers, results-family clustering, routine fold.
   - `test_classify.py` runs on ≥ 60 real subjects pulled in step 1, labelled against the reference categories in
     a reviewable fixture file. `test_score.py` covers tier boundaries and overrides.
8. **Jobs:**
   - `push/pipeline.py run_poll`: BSE, dedupe, classify, score, upsert. No cards yet.
   - `jobs.poll`.
   - `jobs.eod`: prices plus NIFTY 50. No alerts yet.
   - `jobs.warm --freeze ISO`, which writes `web/public/demo/`.
9. **CI:** `.github/workflows/push.yml` polls every 15 min from 08:00 to 23:00 IST and hourly otherwise, since

10. **Web:**
    - Next.js (App Router, TypeScript, Tailwind) with the tokens and fonts from §6.5, plus

    - `lib/digest.ts` ports `digest.py`, and a shared fixture proves both produce the same digest.
    - The Brief has a WindowChip (24h / 3d / 7d / custom), headline counts, and Act and Know rows that say "why
      you're seeing this". It also has results-family cards with attachments, RoutineFold, CaughtUp and
      DataModeChip.
    - PWA: manifest, icons, and a minimal service worker that caches the app shell and the demo snapshot.
    - The bottom nav shows only screens that exist.
11. **Deploy:** schema and seed to Supabase, the repo to GitHub with Actions secrets, and the web app to Vercel. I
    check the first scheduled run.

## Phase 2 — Pull foundations: any NSE ticker → number cards, documents ingested

**Goal:** type any NSE symbol and see four number cards (financials, trajectory, balance sheet, cash quality)
with sparklines, in seconds. Tapping a number shows the table row it came from. In the background, the company's
concall transcripts and annual-report sections are fetched, split into cited chunks and stored for Phase 4.

**Build**
1. **Screener fetcher:** `screener_company(symbol)` returns the parsed quarters, P&L, balance sheet, cash flow,
   ratios and top ratios, plus the documents list (annual reports, transcripts, decks by period). It falls back
   from consolidated to standalone when the consolidated view is empty, and caches the HTML per day.
   `pull_bundle(symbol)` wraps it.
2. **`pull/numbers.py`:** builds D2–D5 exactly as in BUILD_PLAN §5 "Deterministic cards". Every number cites
   `TBL-<section>-<metric>-<period>`. Banks and NBFCs hide the EBITDA-style metrics and show their own (financing
   profit and financing margin). `test_numbers.py` runs on saved HTML for one industrial company and one bank.
3. **Documents:**
   - `pull/bundle.py` downloads the last 4–6 transcripts and the latest annual report, and extracts per-page text
     with pypdfium2.
   - `ocr_needed` is set when a page yields too little text.
   - `ar_sections` finds the MD&A and segment pages by their headings.
   - `pull/chunks.py` creates the chunk ids from §6.1, and everything is stored in `docs`.
4. **`pull/run.py` (stage 1):** validates the symbol, writes the four number cards within about 5s, then ingests
   documents in the background. `jobs` rows track progress, and results are reused for 24h.
5. **API on HF Spaces:**
   - `GET /health`.
   - `POST /research/{symbol}` returns 202, or 200 if results are fresh, and 404 `unknown_symbol` when the symbol
     isn't in EQUITY_L.
   - `GET /research/{symbol}`.
   - `GET /receipt` for table-row citations.
   - CORS allows the Vercel origin. The Dockerfile serves on port 7860.
6. **Web:**
   - Look up: a command bar searching symbols and company names in a bundled NSE list.
   - `/c/[symbol]`: the four cards with sparklines. It polls every 2s until ready and falls back to the demo
     snapshot per §6.3.
   - Receipt sheet v1, for table rows.
   - Nav: Brief · Look up.
7. **Research set:** confirm the five tickers have enough transcripts and swap any that don't. `jobs.warm`
   freezes `/demo/research/{symbol}.json`.

**Exit criteria**
- [ ] ASIANPAINT (not in the demo set) shows four cards in ≤ 10s on a warm Space and in ≤ 60s from cold, both measured.
- [ ] HDFCBANK renders without errors, with the EBITDA-style metrics hidden.
- [ ] An unknown symbol gets a clear "not an NSE symbol" state, not an error page.
- [ ] A unit test asserts that every number on the four cards carries a TBL citation, and tapping a number opens
      its row.
- [ ] Each research ticker has ≥ 4 transcripts and its AR sections in `docs`. Any shortfall and any docs that
      need OCR are listed.
- [ ] With the API unreachable, the demo research tickers still render.

**Cut line:** search symbols only (no company names), and skip AR sections beyond MD&A and segments.

## Phase 3 — Push cards and triggers (BUILD_PLAN Phase 2)

**Goal:** the Brief stops listing filings and starts answering them. It shows results with verified QoQ and YoY
numbers, management changes with who the incoming person is, and one-line summaries where they earn the space.
Price, volume and category alerts arrive on Telegram, based on thresholds the investor sets as sentences.

**Build**
1. **Results (`push/results.py`):**
   - A ladder of sources: XBRL, then the results PDF (P2, copy-only), then screener's quarterly table.
   - Units are normalised to ₹ crore.
   - EBITDA is derived in code (PBT + finance costs + D&A − other income, with exceptional items handled) and
     labelled EBITDA* with an `ebitda_note`.
   - Banks use the schema in §5 P2.
   - Validation checks identities (PBT − tax ≈ PAT) and agreement with prior-quarter history. A failure sets
     `verified=false`, and the card reads "unverified — open filing".
2. **Management (`push/mgmt.py`):**
   - Pull P3 facts from the filing.
   - Search Tavily for the incoming person.
   - Apply a deterministic namesake filter: a snippet must mention the company, the new role or a previous
     employer named in the filing.
   - Write the P4 bio with one source URL per bullet.
3. **One-liners (`push/oneliner.py`):** regex first for dividends and bonus/split, P5 otherwise. Every number in
   `line` must appear in the filing text.
4. **Alerts (`push/alerts.py`):**
   - Volume ≥ k × its N-day average, with a minimum average volume.
   - |Move| ≥ X%, optionally relative to NIFTY 50.
   - Per-symbol overrides.
   - One merged price-and-volume alert per symbol per day. Its likely cause is the top-scored filing for that
     symbol in the prior 24h.
   - Category alerts from the pipeline, with dedupe keys.
   - A Telegram sender that includes a deep link into the PWA.
5. **Pipeline:** builds cards for the Act and Know tiers (`card_status` goes pending → ready or failed) and sends
   alerts.
6. **API:** `PUT /settings` and `POST /alerts/{id}/seen`, both behind the X-FINN-Token header.
7. **Web:**
   - ResultsCard (▲▼, source badge, verified state), MgmtCard and OneLinerCard.
   - AlertCard rows at the top of Act.
   - A Rules screen of inline-editable sentences ("Tell me when volume is more than **2×** its **20-day**
     average").
   - Swipe triage (Noted, Snooze) stored in localStorage, with `seen` sent through the API.

**Exit criteria (from BUILD_PLAN Phase 2)**
- [ ] For three portfolio companies' Q2 FY27 results, the card shows Revenue, EBITDA*, PBT and PAT with QoQ and
      YoY. Every figure matches the filing, shown in a hand-check table in the report. The source badge is shown
      and `verified` is true.
- [ ] A deliberately corrupted history value turns the card "unverified — open filing".
- [ ] A senior management-change filing shows incoming and outgoing people. Each bio bullet links to a source, and
      the namesake filter has unit tests.
- [ ] Setting volume to 1.2× in Rules and running `jobs.eod` sends ≥ 1 alert to Telegram, with a likely cause when
      a filing exists.
- [ ] Turning `relative_to_index` on or off changes which price alerts fire on a fixture market-wide down day.
- [ ] `test_results.py` (XBRL fixture, PDF fixture, unit normalisation, bank schema), `test_alerts.py` and
      `test_mgmt.py` pass.

**Cut line:** drop whichever filing rung (XBRL or PDF) the Phase 1 spike showed is less reliable (the screener rung
stays), Snooze (keep Noted), and the per-symbol override UI.

## Phase 4 — Pull analysis: Promise ledger and Receipts (BUILD_PLAN Phase 3)

**Goal:** for any NSE company with transcripts, FINN shows four things:
- what management promised over the last four quarters, against what was delivered;
- where the story and the numbers diverge;
- a bull and a bear case;
- a one-line verdict.

Every number and claim opens its source page.

**Build**
1. `pull/prompts.py` holds P6–P12 verbatim from BUILD_PLAN §5 plus the grounding preamble, versioned by
   `FINN_PROMPT_VERSION`.
2. `pull/numcheck.py` (§6.4) strips numbers that aren't in the card's inputs and citations that weren't provided.
   A card that loses more than half its content is marked failed.
3. `guidance.py` (P7) and `claims.py` (P8) run once per transcript, cached by document hash. `snapshot.py` runs P6.
4. `ledger.py`:
   - merges P7 outputs into threads (metric + horizon);
   - maps threads to table metrics;
   - computes deterministic verdicts and revisions;
   - calls P9 (strong) only for undecided items and the notes.
5. `narrative.py` runs P10 (strong). `bullbear.py` runs P11 (strong), with only finished cards as input.
   `verdict.py` runs P12.
6. `run.py` stage 2 follows §6.2, with a status per card and specific gap reasons ("No concall transcripts filed
   in the last 12 months").
7. `GET /receipt` serves document pages: the page text with the quote fuzzy-matched and highlighted.
8. **Web:**
   - Research in verdict-first order: Verdict, PromiseLedger (threads × quarters, verdict chips, revision
     markers), Narrative, Snapshot, number cards, Guidance, BullBear.
   - SectionChips and GapNotice.
   - The Receipt sheet extended to document pages.
   - Push cards gain "Dig in", which opens `/c/[symbol]#section`.
9. A CI grep fails the build if anything in `pull/` imports a search or news client.

**Exit criteria (from BUILD_PLAN Phase 3)**
- [ ] For all 5 research tickers, the ledger shows ≥ 4 guidance threads across 4 quarters with verdict chips.
      At least one ticker has a missed or partial item, and at least one shows a revision.
- [ ] 20 sampled taps on numbers and claims each open a Receipt with the quote highlighted, with 0 misses.
- [ ] `test_numcheck.py` (fabricated numbers removed) and `test_ledger.py` (the delivered, beat, partial, missed
      and pending boundaries) pass.
- [ ] A company without transcripts shows gap notices on the guidance and ledger cards, and the other cards render.
- [ ] A second view of the same ticker makes zero LLM calls, with log evidence.
- [ ] The grep check finds no web, news or search code in `pull/`.
- [ ] The cost of one research run is recorded, split between the cheap and strong tiers.

**Cut line:** Snapshot (P6) goes first, then Bull/Bear (P11). The ledger, receipts and numcheck are never cut,
because they're the core of the submission.

## Phase 5 — Reliability, polish and submission (BUILD_PLAN Phases 4 + 5)

**Goal:** it survives a reviewer pointing it at a ticker nobody tried, on their phone, on a day the scrapers are
down. The submission package is complete.

**Build**
1. **Generalisation:** `test_generalise.py` runs over 30 random Nifty 500 symbols (5 financials, 5 small caps,
   2 recent listings) and reports pass, gap or fail per card. Every unhandled exception gets fixed.
2. **Reliability:**
   - `keepalive.yml` pings HF `/health` and touches Supabase.
   - Cold-start time is measured after 48h idle.
   - `test.yml` CI runs pytest and `npm run build`.
3. **Ask FINN (P13):** BM25 over the cached chunks and table rows, opened from the Receipt sheet and from the card
   overflow menu. `POST /ask` includes the not-found path.
4. **Watch:** the portfolio sorted by attention (open Act items, alerts, distance to thresholds, last results
   verdict), with sparklines.
5. **Feedback loop:** after repeated "Noted" swipes on a category, offer "Show dividends as routine?", which
   updates `settings.weights`.
6. **Polish:** empty and loading states, dark mode (§6.5), and a performance pass to reach Lighthouse mobile
   Performance ≥ 85. Check installability on Android and iOS.
7. **Cost:** `docs/cost.md` from `usage_summary()`, in ₹, covering warming all demo tickers plus one day of Push.
8. **Submission (BUILD_PLAN §8):**
   - Re-freeze the snapshot at a results-rich moment.
   - README: 3-line pitch, link and QR code, 4 screenshots, architecture, setup, deploy, limitations.
   - `docs/build-history/`, with keys scrubbed. A Vercel token was pasted into the chat on 3 Nov, so it gets
     revoked in Vercel (and a new one used) before these logs are published.
   - `docs/writeup.md` per §8.4, with the measured costs.
   - A secret scan.
   - A demo-fallback test with `NEXT_PUBLIC_API_URL` pointed at a dead host.
   - **You:** the real-phone test on iOS Safari and Android Chrome, the 2-minute video, and sending the
     email.

**Exit criteria**
- [ ] `test_generalise.py` gives 0 page crashes. Every per-card failure has a reason, and none is an unhandled
      exception.
- [ ] Ask FINN answers "What did management guide for margins?" with citations, and returns `not_found` for an
      unrelated question.
- [ ] Lighthouse mobile Performance is ≥ 85, and the app installs on Android and iOS.
- [ ] `docs/cost.md` has the measured ₹ total.
- [ ] The demo fallback works with live services down.
- [ ] CI is green, the history has no secrets, and the README and writeup are complete.

**Cut line:** Watch and the feedback loop go first, then Ask FINN. `test_generalise.py`, the fallback and the
